# Misa AOT compilation (v0.3)

`misa build <file.misa> [-o output]` compiles a Misa program to a
native machine-code binary ahead of time, through LLVM. This is Misa's
flagship execution mode. Required system libraries vary with the build
target and enabled runtime features; a native executable is not necessarily
a fully self-contained static binary.

## Pipeline

```
.misa source
  → parse + static check (same frontend as `misa run`; all E1xx/E2xx
    diagnostics apply unchanged)
  → LLVM IR (generated by impl/misa/aot/emit.py via llvmlite)
      (verified, optimized MIR lowers eligible pure scalar Int/Float functions;
       unsupported functions use the established direct emitter)
  → LLVM module optimization (speed level O2; strict floating-point semantics)
  → native object file (LLVM target machine)
  → link with the C runtime (impl/misa/aot/rt/)
  → executable
```

`misa build --emit-llvm file.ll` dumps the generated LLVM IR for
inspection. The IR is ordinary LLVM: `misa build` targets the host
triple today; other triples (e.g. `aarch64-apple-darwin`) are a
build-configuration change, not a redesign — the IR itself is portable.

## Value representation

Generic Misa values use the tagged, garbage-collected `MVal`
representation (a single `i8*` in generated code). The tag tells the
runtime what it is: `Int` (64-bit), `Float`, `Bool`, `Text` (byte string
with explicit length), `List`, `Map`, `Record`, catchable `Error`,
`Null`, and media handles. The AOT emitter keeps eligible local `Int`
and `Float` values unboxed and uses specialized paths for some typed
arrays and record fields; generic aggregates still use runtime helpers.

`Int` is 64-bit two's-complement (wrapping) on both backends
(C-1 audit decision, 2026-10-06): literals, arithmetic, and `int()`
parsing all wrap identically in the interpreter and AOT. Out-of-range
`Float`→`Int` conversion is E300. See `SEMANTICS.md`.

## Memory management

When Boehm GC development headers and a linkable library are available,
the host runtime allocates through `GC_malloc`; generated code keeps values
in LLVM allocas and the C stack, which Boehm scans as roots. On Debian or
Ubuntu, install `libgc-dev` to enable this mode. Misa does not currently
download or build the collector automatically.

If Boehm headers are absent, the runtime deliberately degrades to plain
`malloc` without collection. In that fallback, temporary boxed values are
not reclaimed during process execution and allocation-heavy programs can
consume substantially more memory. The benchmark JSON records the selected
memory manager and collector package version; comparisons must keep this
setting fixed. The fallback is useful for portability, not a recommended
configuration for long-running or allocation-heavy programs.

## Errors

AOT uses the same catchable-error model as the interpreter:
`try`/`catch`/`throw`, and every runtime/model/budget/IO failure is a
catchable `Error { code, message }`. Implementation: a pending-error
flag. Every fallible runtime call is followed by a check that branches
to the innermost handler (a `catch` block, or the function epilogue
which returns immediately and propagates). There is no stack unwinding
tables or exception ABI involved.

An error that is never caught aborts the program: the runtime prints

```
<line>:<col>: <code>: <message>
```

to stderr and exits 1 — the same shape as `misa run`, except AOT
reports the precise source location of the failure where the
interpreter reports `<unknown>`.

New error codes:

- `E402` — streaming (`stream`, `await`, `on`) is not supported in AOT
  v0.3. This reuses the interpreter's streaming-unsupported code.
- `E600` — AOT-internal failure (link errors, emitter limitations).
  Never raised for ordinary program errors.

## Model calls

`model` declarations compile to **blocking** calls. The emitter bakes
the declaration (provider, alias, budgets, return-type schema, prompt
template) into the binary as metadata; at runtime the call:

1. renders the prompt (parameter interpolation; `Photo` params whose
   file exists are sent as images),
2. POSTs to the provider over HTTPS (`openai` →
   `/chat/completions`; `gemini` → `:generateContent`),
3. parses the JSON response with the runtime's own JSON parser,
4. validates it against the declared return type (same rules as the
   interpreter, including the up-to-2 repair retries with the same
   repair prompt),
5. enforces token/latency/cost budgets (`E500`).

Provider keys come from the environment variables named in the
`provider` block, exactly as with `misa run`. `MISA_OPENAI_BASE_URL`
and `MISA_GEMINI_BASE_URL` overrides are honored. The `mock` provider
reads scripts from the file named by `MISA_MOCK_FILE`, so AOT model
logic is testable without network or keys.

Streaming model calls are rejected at build time with `E402`.

## Coverage

v0.3 AOT supports the full v0.2 language **except streaming**:
functions (typed returns, recursion, `Void`), modules, `try`/`catch`/
`throw`, `Map`, records, lists, text (Unicode-aware), all builtins,
`fs.read`/`fs.write`, `http.get`, screens (same text preview tree as
the interpreter), and blocking model calls with budgets.

## Deliberate divergences from the interpreter

These are cases where AOT is intentionally stricter or more precise.
Each is a documented improvement, not a gap:

- **Integer division/modulo by zero** raises catchable `E300`. The
  interpreter crashes with a raw Python `ZeroDivisionError`.
- **Type errors in arithmetic/comparison** (e.g. `"a" - "b"`) raise
  catchable `E200`. The interpreter crashes with a raw Python
  `TypeError`.
- **Uncaught errors carry the source line and column** (`12:3: E305:
  …`) where the interpreter prints `<unknown>`.
- **`Int` is 64-bit wrapping** on both backends (C-1 audit decision).
- **Prompt interpolation** in `model` blocks accepts parameter names
  only (same as the interpreter).
- **First-class lambdas** (`let f = (x) => x`) are rejected with
  `E402`; lambdas remain available as component event handlers
  (`onTap: || { … }`), printed as `<handler>` like the interpreter.

## Binary and startup measurements

Binary size and cold-start time depend on LLVM, the C toolchain, garbage
collector configuration, and linked runtime features. Use `misa benchmark`
to measure them on the target host. Its JSON records source revision,
toolchain versions, sample distributions, and allocator mode; do not treat
old single-host figures or comparisons with unrelated application
frameworks as general performance claims.

## Not yet

- Full cross-target builds: `misa build --target <triple>` (see
  `misa build --list-targets`) emits relocatable objects for
  wasm32-unknown-wasi, wasm32-unknown-emscripten,
  aarch64-linux-android, armv7-linux-androideabi, and both Apple
  triples; linking per target arrives with Phase 4 M3/M6/M7. The
  runtime itself is now retargetable: host-OS assumptions live behind
  `rt/misa_platform.h` (one implementation per target;
  `rt/platform_linux.c` keeps today's behavior) and screens render
  through the `rt/misa_ui.h` driver interface (`rt/ui_text.c` is the
  default text driver, byte-identical to the old stdout tree).
- Streaming model calls (`stream`/`await`/`on`).
- A precise (non-conservative) GC and unboxed value representations.
- More aggressive representation-level optimization (e.g. primitive
  record layouts and broader unboxed typed arrays).
